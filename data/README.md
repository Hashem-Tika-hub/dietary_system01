# تنظيم بيانات المشروع

> يحتوي هذا المجلد على **ملفات بيانات قابلة للتتبع** فقط. قاعدة البيانات المحلية، الأرشيفات الكبيرة المؤقتة، والأسرار لا تُحفظ في Git.

## البنية

```text
data/
├── catalog/                     # نسخة SQLite مرجعية قابلة للمراجعة
│   ├── food_catalog_reference.sqlite3
│   └── food_catalog_reference.manifest.json
├── raw/                         # مصادر قبل التنظيف أو التحويل
│   ├── local_food_source.csv     # قائمة الأطعمة المحلية الأولية
│   ├── collected/foods_raw.csv   # ناتج جمع خام قابل لإعادة المعالجة
│   └── external/                 # خمس مجموعات CSV خارجية أصلية
├── processed/
│   └── foods_clean.csv           # كتالوج معالج لمدخل CBF واستيراد CSV
├── fixtures/
│   └── synthetic_users.csv       # أمثلة مستخدمين اصطناعية فقط
└── outputs/                      # مخرجات تحليل وتجارب قابلة لإعادة الإنشاء
    ├── analysis/
    │   ├── charts/               # مخططات الاستكشاف والتجارب
    │   └── dataset_stats.txt     # ملخص الكتالوج المعالج
    ├── evaluations/
    │   └── evaluation_results.csv
    └── plans/                    # خطط أسبوعية توضيحية مولّدة
```

## وظيفة الملفات

| الطبقة | المحتوى | الوظيفة | المنتج أو المستهلك | ملاحظة جودة مهمة |
|---|---|---|---|---|
| `catalog/food_catalog_reference.sqlite3` | نسخة علائقية للكتالوج فقط | مراجعة الجداول والأطعمة والمغذيات والمصادر عبر SQLite/DB Browser | ينتجها `scripts/build_reference_food_catalog.py` | لا تحتوي مستخدمين أو سجلات وجبات أو خططًا أو تفضيلات. ليست قاعدة التشغيل. |
| `catalog/food_catalog_reference.manifest.json` | بيان تتبع وبصمة SHA-256 | التحقق من النسخة ومصادرها وعدد صفوفها | ينتجه باني النسخة المرجعية | راجع البصمة بعد أي تعديل يدوي أو إعادة بناء. |
| `raw/local_food_source.csv` | أطعمة محلية ببيانات أولية | نقطة بداية لتنظيف الكتالوج المحلي | يقرأها `03_clean_data.py` | القيم المحلية تحتاج مصدرًا موثقًا قبل أي ادعاء سريري. |
| `raw/collected/foods_raw.csv` | نتائج جمع أولية | لقطة خام يمكن إعادة تنظيفها أو دمجها | يكتبها `02_collect_data.py` ويستخدمها `02b_merge_external.py` | ليست مصدر API مباشرًا. |
| `raw/external/*.csv` | خمس مجموعات غذائية خارجية أصلية | مادة إدخال تاريخية لدمج البيانات | يقرأها `02b_merge_external.py` | قد تحتوي أطعمة لا تناسب سياسة المشروع؛ لا تصل للتوصية إلا بعد القيود الصلبة. |
| `processed/foods_clean.csv` | 456 صنفًا معالجًا | مدخل CBF الافتراضي واستيراد كتالوج CSV | `03_clean_data.py` و`ml/core` و`scripts/import_food_catalog.py` | API نفسه يقرأ قاعدة البيانات العلائقية، لا CSV مباشرة. |
| `fixtures/synthetic_users.csv` | 300 مستخدم اصطناعي | اختبار K-Means وأدوات التدريب التاريخية | `ml/core/user_profiler.py` و`06_kmeans_model.py` | لا يمثل مستخدمين حقيقيين ولا يُستخدم لتفعيل Collaborative Filtering. |
| `outputs/analysis/charts/` | 13 مخططًا | لقطات تحليل وتوثيق للمشروع | تنتجها أدوات الاستكشاف والتدريب | مخرجات قابلة لإعادة الإنشاء، وليست مدخلات تشغيل. |
| `outputs/analysis/dataset_stats.txt` | إحصاءات الكتالوج | توثيق نتيجة التنظيف | ينتجه `03_clean_data.py` | يعاد توليده عند تحديث الكتالوج. |
| `outputs/evaluations/evaluation_results.csv` | نتائج تقييم تاريخية | عرض مقاييس تجربة التوصية | ينتجه `10_evaluate.py` | لا يعد مقياس فعالية طبية أو رضا مستخدمين حقيقيين. |

## قواعد الاستخدام

يجب أن تبدأ أي معالجة جديدة من `raw` وتكتب النسخة الصالحة للتدريب أو الاستيراد في `processed`. أما التقارير والمخططات والخطط التجريبية فتكتب في `outputs`، ولا يجوز أن يعتمد عليها API أو محرك التوصية كبيانات مصدر.

تطبّق قيود الحساسية والاستبعاد الثقافي قبل ترتيب المرشحين. لا يكفي وجود طعام في `processed/foods_clean.csv` ليكون مناسبًا لمستخدم لديه حساسية أو ليحمل وصفًا بأنه حلال معتمد. تحتاج بيانات المكونات أو أدلة الحساسية أو شهادة الحلال إلى مصدر مستقل ومراجع.

## مراجعة نسخة الكتالوج

يمكن فتح `catalog/food_catalog_reference.sqlite3` ببرنامج SQLite أو DB Browser for SQLite ومراجعة جداول `catalog_sources` و`foods` و`food_nutrients` و`food_portions` و`allergens`. تؤكد الأداة البانية قبل حفظ النسخة أن جداول `users` و`meal_logs` و`weekly_plans` و`user_food_feedback` فارغة، وأنه لا توجد مخالفات مفاتيح خارجية.

لإعادة بناء النسخة من المصدرين الحاليين، شغّل `python scripts/build_reference_food_catalog.py --download-usda`. ينزّل الأمر أرشيف USDA مؤقتًا فقط ثم يبني النسخة والبيان. لا تضع `DATABASE_URL` للتطبيق على هذا الملف؛ استعمل قاعدة تشغيل منفصلة قابلة للكتابة لبيانات المستخدمين.

## ما لا يوضع هنا

لا تُضف قواعد SQLite المحلية أو قواعد التشغيل القابلة للكتابة، أو `.env`، أو أرشيفات USDA الكبيرة، أو نماذج التدريب الثنائية إلى هذا المجلد. الاستثناء الوحيد هو `catalog/food_catalog_reference.sqlite3`، وهي نسخة كتالوج ثابتة ومراجعة بلا أي بيانات مستخدم. تحفظ النماذج القابلة لإعادة الإنشاء ضمن `models/` حاليًا إلى أن تُنقل في دفعة مستقلة إلى `artifacts/models/`، وتبقى أرشيفات الاستيراد المؤقتة خارج المستودع.
