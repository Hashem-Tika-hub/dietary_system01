# نتائج قياس أداء API محليًا

## نطاق القياس

أُجري القياس باستخدام `FastAPI TestClient` مع قاعدة `SQLite` مؤقتة محلية، بعد خمس طلبات تسخين، ثم خمسين طلبًا متسلسلًا لكل endpoint. يقيس ذلك زمن التوجيه والتحقق والتحويل التسلسلي والوصول المحلي إلى قاعدة البيانات. **لا يقيس** زمن الشبكة أو TLS أو قاعدة بيانات خارجية أو التحقق الكامل من JWT أو تحميل/استدلال نماذج تعلم الآلة.

> هذه أرقام baseline للتطوير المحلي وليست SLA للنشر. يجب إعادة القياس عبر بيئة staging مطابقة للإنتاج بعد اختيار خادم وقاعدة بيانات ومعدل حمل مستهدف.

## النتائج

| Endpoint | الحالة | المتوسط (ms) | الوسيط (ms) | P95 (ms) | P99 (ms) | الحد الأقصى (ms) |
|---|---:|---:|---:|---:|---:|---:|
| `GET /users/profile` | 200 | 1.773 | 1.752 | 2.254 | 2.382 | 2.382 |
| `GET /users/meal-logs` | 200 | 3.134 | 3.020 | 4.251 | 4.895 | 4.895 |
| `GET /users/meal-logs/summary` | 200 | 3.739 | 3.517 | 5.671 | 6.530 | 6.530 |
| `POST /users/meal-logs` | 201 | 6.431 | 6.287 | 8.469 | 9.769 | 9.769 |
| `POST /users/food-feedback` | 201 | 5.398 | 5.316 | 6.866 | 7.979 | 7.979 |
| `GET /users/food-feedback/readiness` | 200 | 3.063 | 2.869 | 3.910 | 7.779 | 7.779 |

الكتابة هي الأبطأ طبيعيًا لأنها تتضمن إنشاء سجل ومعاملة SQLite وتأكيدها. بقي `POST /users/food-feedback` أخف من إضافة سجل وجبة، بينما بقيت قراءات الملف والسجل والملخص وحالة الجاهزية منخفضة في هذه البيئة المحلية. لا تشمل النتائج endpoint التوصية؛ إذ إن قياسه بصورة عادلة يتطلب كتالوجًا فعليًا ونموذج محتوى محملًا، ويجب فصله إلى **زمن فلترة/ترتيب** و**زمن API الكلي** عند توفر بيانات التشغيل.

## إعادة تشغيل القياس

```bash
python3 scripts/benchmark_api.py
```

يحفظ السكربت الأرقام الخام في `reports/api_benchmark_local.json`. لا تستخدم ملف النتائج لاتخاذ قرار سعة إنتاجية قبل إضافة قياس متزامن مع قاعدة بيانات الإنتاج ومصادقة JWT فعلية.
